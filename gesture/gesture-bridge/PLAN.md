# 隔空过桥 · 移项解方程 —— 策划案 v1（待确认）

> 项目代号：`gesture-bridge` ｜ 形态：单页纯静态网页（离线可跑）｜ 定位：**手势操作型**课堂教具
> 一句话：学生站在屏幕前，**用手把项"搬"过等号**——搬过去必须变号，等式两边实时保持平衡。

## 一、输入盘点（我看了什么）

### 1. 视频（35 秒 · 1070×946 · 120fps）
标题即主题：**「谷歌 MediaPipe Hand Landmarker：普通摄像头就能实现隔空取物的魔法」**。拆解出 7 个镜头：

| 镜头 | 内容 | 可借鉴点 |
|---|---|---|
| 1 | 手掌隔空抓取、旋转粒子球 | 「抓取—搬运」是这个视频的核心动作语言 |
| 2 | Gemini 网页生成 | 20 行网页就能起一个手势 demo，门槛已塌 |
| 3 | 手掌前 21 个 3D 关键点（画面上叠了键盘/鼠标 UI） | 21 点即"虚拟鼠标"，光标映射是基础能力 |
| 4 | 手一挥，电脑立刻响应；手部动作控制 3D 图案 | 大动作比精细点击更稳、更有表现力 |
| 5 | 召唤光球、隔空打游戏 | 「隔空取物」的审美：浮起、拖尾、光效 |
| 6 | 手机能跑、网页能跑、开发板也能跑 | 纯浏览器方案即可，不依赖专用硬件 |

**结论**：视频提供的不是"新识别能力"，而是**动作语言**（抓取、拖拽、隔空触碰）与**审美参考**（浮起的物件、拖尾光标）。
我们已经有同样的引擎，差异化只能来自"手势承载什么数学语义"。

### 2. MediaPipe 现状（与本地引擎核对）
- 官方 JS 包 `@mediapipe/tasks-vision`：`FilesetResolver` + `HandLandmarker.createFromOptions`，`runningMode:'VIDEO'`、`numHands`、`delegate:'GPU'`（失败降级 CPU）——**你项目里已在用**。
- `hand_landmarker.task` 约 7.8MB；`lib/` 含 wasm 运行时约 18MB，**已本地化，断网可跑**。
- 每个结果给 `landmarks`（归一化 2D）、`worldLandmarks`（米制 3D）、`handednesses`。**判定手指/捏合要用 worldLandmarks**，2D 投影会把手指压短（gesture-edu 的 README 已经踩过这个坑）。
- 另有 GestureRecognizer（内置握拳/张开手掌/食指向上/点赞等固定类别）、Face/Pose Landmarker。**本项目不用预置手势分类**——教学需要的是"位置/距离/抓取"，不是 7 个固定手势。
- 官方文档：[Hand Landmarker](https://ai.google.dev/edge/mediapipe/solutions/vision/hand_landmarker) ｜ [Gesture Recognizer](https://ai.google.dev/edge/mediapipe/solutions/vision/gesture_recognizer) ｜ [仓库](https://github.com/google-ai-edge/mediapipe)

### 3. 你自己的三个手势项目（交互基因）
| 项目 | 手势原语 | 交互范式 | 使用角色 |
|---|---|---|---|
| `gesture-demo` 空中画函数 | 掌心位置 / 指尖轨迹 / 双手对碰 | **脚本化舞台演示**（固定 7 幕） | 老师（报告开场） |
| `gesture-edu` 课堂反馈 | 手指数 1~4（四指判据） | **离散选择 + 聚合统计** | 全班学生 |
| `gesture-shudu` 手势数独 | 指尖光标 + 捏合 | **精细点选** | 单个学生 |
| `gesture-shudu/index` 巨型全息 | 双手 | 粒子视觉 | 展示 |

**共性**：都是"手 → 光标/数量"，手是**输入设备**。
**空白**：还没有一个页面让手势**直接等于数学操作**（搬运、跨越、对称）；也没有一个页面解决"精细点选不稳"的老问题（数独就是精细点选，课堂上最容易失手）。

## 三、方案主张：为什么"移项"值得用手势做

**选题**：人教版七上《解一元一次方程（一）——合并同类项与移项》。学生最高频、最致命的错误是**移项忘记变号**。

1. **手势与数学规则天然同构**：把项从等号一边"搬"到另一边，就是"过桥变号"。文字口诀记不住，一个动作能记住——**身体记忆 > 口头记忆**（具身认知）。
2. **手势不可替代**：鼠标也能拖，但"站起来、伸手、搬过桥"带来的是全班可见的**公开操作**，且老师不用回到电脑前。
3. **鲁棒性最好**：判定事件是"卡片越过中线"这个**大空间事件**，不需要精确落点；系统自动重排，容错极高。
4. **可无限出题**：一元一次方程好生成、好判题、好讲评，一节课能跑 8~12 题。
5. **可扩展到整章**：同一套"搬运"引擎能扩成"两边同除（双手合拢）"「去括号（手掌抹开）」，形成"用身体操作等式性质"的系列。

> 与 `gesture-demo` 的区别：那个是**画**函数给 AI 拟合（输入→生成）；这个是**搬**数学对象、维持等式（操作→验证）。
> 与 `gesture-edu` 的区别：那个是**离散选择**（1~4 指）；这个是**连续拖拽 + 空间判定**。
> 与 `gesture-shudu` 的区别：那个是**精细点选**（易失手）；这个是**大目标 + 自动吸附**（刻意反着来）。

## 四、手势语言（v1）

| 手势 | 判定（用 worldLandmarks，阈值以"掌宽"归一化） | 数学语义 | 屏幕反馈 |
|---|---|---|---|
| 指向 | 食指伸直、中指弯曲；指尖落在大卡片上保持 0.2s | 选中一项 | 卡片浮起、外发光 |
| 捏合抓取 | 拇指尖—食指尖距离 < 0.06 掌宽，连续 4 帧 | "抓住"这一项 | 卡片锁定，跟手，出现拖尾 |
| 拖动 | 指尖位置 EMA 平滑（α=0.35）后映射到屏幕 | 搬运 | 经过时桥面亮起、涟漪 |
| 松手 | 捏合距离 > 0.10 掌宽，连续 4 帧 | 放下 | 卡片落位，符号翻转动画 `+5 → −5` |
| 跨线 | 卡片中心越过等号线 ± 8% 缓冲带（迟滞） | **移项（等式性质 1）** | 过桥光效 + "两边同减 5"的板书追加 |
| 双手合拢 | 两掌心距从 >1.2 掌宽收到 <0.5 掌宽，连续 6 帧 | **两边同除以系数（等式性质 2）** | 等式两边整体缩放动画 |
| 张开手掌保持 1s | 五指伸直（复用 gesture-edu 判据） | 确认 / 继续 | 顶部状态"已就绪"，进入下一题 |

**防抖组合拳**（沿用你项目已验证的四件套，再加两条）：
1. 稳定帧（3~6 帧）+ 动作冷却（0.5s）+ "松开才生效"；
2. 捏合阈值用**掌宽归一化**，适应学生高矮远近；
3. **只认一只"操作手"**：取画面下方中央区域、离中心最近的手；其它手只做幽灵显示，不参与判定（避免多人入镜互相干扰）；
4. **过桥带迟滞**，避免手在线上抖动时来回触发；
5. **丢手保护**：卡片跟随中丢手 300ms 自动回原位，**不算出错**；
6. 所有阈值集中在 `CONFIG`，README 给"学生手小/光线暗"的调参指引（照抄 gesture-edu 的写法）。

## 六、课堂脚本（约 8 分钟，可直接写进说课稿）

1. **出题**：投出 `3x + 5 = 2x + 11`，问"下一步做什么？"（学生：把 5 移到右边）。
2. **上台**：一名学生站到屏幕前，伸手 → 光标出现 → 悬停 `+5` → 捏合。
3. **过桥**：把卡片拖过等号线，松手 → `+5` 翻成 `−5` 落到右边，板书追加一行。
4. **追问**：为什么能变号？点开"等式性质 1"卡片 → 天平动画演示**两边同减 5**，见证等价。
5. **故意犯错**（挑战模式）：同一动作但"不变号" → 天平立刻歪、卡片红闪 → AI 一句"过桥忘变号，等式不成立了"。
6. **收尾**：`3x−2x=11−5` → `x=6`，双手合拢做"两边同除"演示；再练 2 道变式（x 在右边、带负号）。
7. **复盘**：导出本课步骤记录（CSV），投影全班错误类型分布。

## 七、题目与关卡

| 关卡 | 题型 | 例题 | 训练点 |
|---|---|---|---|
| L1 单移项 | 常数过桥 | `x + 5 = 12`、`3x = x + 8` | 过桥变号 |
| L2 双移项 | 两边都有未知数 | `3x + 5 = 2x + 11`、`4x − 2 = 2x + 6` | 移项方向选择 |
| L3 移项+合并 | 同类项合并 | `5x − 3 = 2x + 9` | 合并与移项顺序 |
| L4 系数化为 1 | 双手合拢同除 | `2x = −8`、`−3x = 12` | 等式性质 2 |
| L5 变式（v1.1） | x 在右、带括号 | `7 − 2x = 3`、`2(x+3)=x+9` | 易错变式 |

- 题库内置 12 题 + **程序生成器**（随机整数解、保证最少 2 步），可"再来一题"。
- **判题引擎不写死步骤**：用 3~5 个随机 x 值代入，检验每一步前后等式是否恒等（数值等价校验）。学生哪怕用非常规顺序，只要每步等价就放行——这才是"操作型"教具该有的宽容度。

## 八、反馈与诊断

- **即时**：卡片落位 → 符号翻转动画 → 板书追加 → 天平平衡/倾斜。
- **本地诊断规则**（覆盖 6 类错误，不依赖网络）：
  E1 过桥不变号 ｜ E2 移错边 ｜ E3 合并符号错 ｜ E4 漏项 ｜ E5 同除只除一边 ｜ E6 未检验
- **AI 点评**：默认用本地话术模板；预留"接 DeepSeek"的接口（与 `ask-only-tutor` 一致的做法）。
  ⚠️ 纯静态页**不能把 API Key 写进前端**；若接 AI，走本地代理（如 `qidian` 的 Node 服务模式）或教师本人填 key 的本地存储，README 写清风险。
- **记录**：每题"用时 / 步数 / 错误类型 / 是否一次通过"，可导出 CSV / Markdown。

## 九、技术实现

| 项 | 方案 |
|---|---|
| 引擎 | 复制 `gesture-demo/lib` + `model`（同一版本，18MB + 7.8MB），`HandLandmarker` GPU→CPU 降级 |
| 页面 | 单文件 `index.html`（内联 CSS/JS），无 CDN、无构建、离线可跑 |
| 渲染 | 等式卡片/板书用 DOM + CSS transform（便于无级缩放与键盘可访问）；手部光标、拖尾、涟漪用 canvas 叠层 |
| 坐标 | 摄像头画面水平镜像；手部归一化坐标 → 屏幕坐标带灵敏度增益（CONFIG 可调） |
| 状态机 | `IDLE → HOVER → GRAB → DRAG → RELEASE → SETTLE → JUDGE → IDLE`，每题一个 `EquationModel` |
| 彩排 | `?demo=1` 合成手部关键点跑完整流程（照抄 gesture-edu 的彩排模式），界面常驻"彩排模式"角标 |
| 调试 | `?debug=1` 显示骨架、掌宽、捏合距离、过桥带 |
| 兜底 | 鼠标点击卡片→点目标位置；键盘 `Tab/Enter` 选中与移动、`←/→` 换题、`R` 重来；所有按钮可点 |
| 隐私 | 摄像头画面不出浏览器、不上传、不落盘 |
| 性能 | 摄像头 640×480@30，检测每帧一次，目标 ≥30fps；页面 60fps |
| 自检 | 新增 `tools/test-equation.js`（node 测判题引擎），`verify.sh` 的 `PAGES` 加一行 |

**文件结构**
```
gesture/gesture-bridge/
├── index.html          # 页面本体（单文件逻辑）
├── README.md           # 怎么跑 / 手势表 / 调参 / 现场彩排要点
├── lib/                # 从 gesture-demo 复制的识别引擎
```

## 十二、风险与对策

| 风险 | 对策 |
|---|---|
| 学生手小/光线暗识别不稳 | 掌宽归一化阈值；小窗实时提示"手太小/太暗"；CONFIG 调参表 |

## 十三、备选方案（如果选题想换）

| 方案 | 手势语言 | 教学点 | 亮点 | 风险 |
|---|---|---|---|---|
| **A. 隔空变换台** | 单手拖=平移；双手连线=旋转；双手距离=相似比 | 平移/旋转/相似/位似，坐标规律 | 双手协作、变换参数实时可视化、与"图形变换"单元强相关 | 映射需要引导层；视觉强于教学 |
| **B. 抓顶点调参** | 抓顶点拖→改 h、k；双手拉开→改 a | 二次函数 `y=a(x−h)²+k` | 手感极直观，"抓住抛物线" | 与 gesture-demo 同为函数题材 |
| **C. 隔空向量合成** | 双手各成一个向量 | 向量加法/平行四边形法则/力的合成 | 双手＝两个向量，数学上优雅 | 适用面偏窄（高一） |
| **D. 隔空三视图** | 手掌朝向旋转 3D；双手拉开缩放 | 三视图/截面/空间想象 | 视觉最像视频里的 3D 操控 | 手掌朝向噪声大，鲁棒性最差 |

> 若你主要教**高中**，我建议把主方案换成 **B（二次函数）** 或 **C（向量）**，引擎与页面骨架可以直接复用，只换教学对象。

| 捏合抓取 | **握拳抓取** | 复用 `gesture-edu` 已验证的四指判据（指尖到手腕 > 第二关节到手腕），对光照和手掌朝向更宽容；"抓住"的动作语义也更直白 |
| 指尖悬停选卡 | **掌心中心悬停** | 指尖位置随手指姿态跳变，掌心中心稳定；卡片目标足够大，不需要指尖精度 |
| 光标按屏幕比例映射 | **按摄像头宽高比等比映射** | 横向/纵向手感一致，不会出现"左右快、上下慢" |
| 挑战模式（v1.1） | **v1 已含** | 过桥后比 1 指=变号、2 指=不变；答错时等号抖动 + 1.9 秒后自动撤销，是课堂上最有价值的一幕 |
| 双手合拢同除 | **v1 已含** | 两掌心距从 >30% 收到 <16% 且保持约 0.46 秒触发，带迟滞防误触 |
| 去括号 / L5 变式 | 未做（v1.1） | 先把"过桥变号"这条主线做扎实 |

**额外交付**（策划里没有、但工程上必须有）：
- `?selftest=1` 方程引擎自检（11 项）：移项变号、等价校验、同除、随机题目生成；
- `?autotest=1` 交互链路自测：用假时钟以 60fps 驱动"抓取→过桥→变号→合并→同除→解出"，跑通 4 道题；
- `?shot=1` 固定画面，用于生成 `previews/gesture-bridge.png`；
- `?debug=1` 暴露 `window.__bridge`，方便维护时在控制台驱动内部状态；
- 判题不写死步骤：每一步用 5 个采样点检验"左右两边之差"是否一致，非常规解法不误判；
- 三套输入（手势 / 鼠标 / 键盘）+ 彩排模式，任何一套都能上完整一节课。

**验证结果**：
- 引擎自检：11/11 通过；
- 交互链路自测：4 道题、0 错误、约 20 秒（假时间）；
- `tools/verify.sh`：53 项通过，仅剩"大运河"页 AMap 线上 Key 失效这条**既有**失败（与本次改动无关）；
- 1280×800 / 1024×768 / 1920×1080 三种投影分辨率均已截图检查；
- 真实浏览器 CDP 跑 `?demo=1` 7 秒，完成 1 道题并进入第 2 题，挑战模式提示条正常。
